# Grayscale test-generation fix — 2026-10-09

A production run rejected four generated test suites despite independent grayscale
pixel and alpha checks passing on the trusted fixture. Two suites expected 35 raw
bytes where the actual 7 × 5 RGBA decode contained 140 bytes. Later assertions also
failed on effect detection and alpha expectations.

The generation contract now explicitly describes the partial-alpha fixture and
requires actual/reference images to be normalized to the same sRGB RGBA layout.
Byte length and indexing must use the decoded info.channels, not an assumed
single grayscale channel. Grayscale references use Sharp rather than an unrelated
handwritten formula. Tests must not overwrite their supplied fixtures.
The sandbox runner supplies frozen input metadata as an optional ninth test
argument. Existing test signatures remain compatible. Repair requests receive a
structured verification report distinguishing model assertions from independent
checks; a passing independent fixture does not excuse failing extra cases.

Discovery generation now states the stable tie-order contract explicitly. The UI
labels its synthetic-data build tests, including saved history, so fixture IDs
cannot be confused with tools installed in the user's registry.

Verified with real OpenAI and Vercel Sandbox, without changing the database or
installing a tool: grayscale code and tests generated by the agent passed on the
first attempt. All four checks passed: model tests, decoding/file limit, dimensions,
and exact operation pixels/alpha. See [evidence](evidence/grayscale-fix.json).

Offline regression coverage includes the 140-byte RGBA decode, preservation of
semi-transparent alpha, and structured repair feedback. All 32 local tests passed.
No failing test is ignored, removed or converted into a successful install.
Changes must be deployed before they affect the production application.
